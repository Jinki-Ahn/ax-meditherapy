# medi-agent — 시딩을 매주 반복되는 인과 실험으로 바꾸는 운영 스킬

이 스킬은 인플루언서 시딩 배치를 '집행 후 관망'이 아니라 처치/대조와 고유 추적 코드가 있는 실험으로 설계하고, 그 결과로 다음 배치의 예산을 옮기는 주간 루프를 돈다. 하는 일의 경계: 실험 설계·브리프·신호 해석·재배분 추천까지가 자동의 몫이고, 어느 커뮤니티를 실험장으로 삼을지·메가 인플루언서 베팅·안전성 플래그 크리에이터의 기용 여부는 인간의 몫으로 남긴다.

## 절차 (5단계)

모든 단계는 `scripts/pipeline.py`가 구현한다. 주간 실행: `python3 scripts/pipeline.py --state-dir <상태 디렉토리> [--data <온톨로지 데이터>] [--budget <원>]`

1. **온톨로지 로드** — `data/ontology/schema.json`으로 입력 데이터를 검증하고 4개 엔티티와 루프 상태(조합 스코어)를 읽는다. 스키마 부적합이면 즉시 중단.
2. **실험 설계(처치 이원화)** — 유사 PX 지점 쌍(pair_group) 안에서 처치/대조를 배정하고, 전국 도달 크리에이터는 게시 시차(0·1·2주)로 식별한다. 조합별 고유 추적 코드를 발급한다. 검정력 미달(배정 쌍 < min_sample) 신호는 제외하고 사유를 보고한다.
3. **브리프 생성** — 크리에이터별로 핵심 메시지 × 커뮤니티 맥락, 금지 표현, 의무 표기(협찬 고지), 추적 코드, 게시 주차를 담은 브리프를 만든다. 핵심 메시지와 커뮤니티의 결합은 온톨로지가 아니라 이 시점에 일어난다(제품 엔티티의 카테고리 중립 유지).
4. **신호 수집** — 선행 신호(검색 리프트·코드 첫 구매·PX 셀스루)와 후행 신호(재구매·후기)를 어댑터에서 읽는다. 데모는 `signal_adapter_mock.py`, 실서비스는 온톨로지 `conversion_signal.acquisition`에 명시된 경로로 어댑터만 교체한다.
5. **이중 루프** — 주간: 선행 신호로 조합(크리에이터×커뮤니티×제품) 스코어를 갱신하고 원당 기대 성과 기준으로 예산을 재배분한다(탐색 슬롯 1명 포함). 분기: 도착한 재구매로 선행 신호의 예측력을 검정(유의성 게이트)해 가중치를 보정한다. 매 회전 수요 증거 패키지(`evidence_package.md`)를 출력한다.

## 도메인 지식

- **인플루언서 3층 스택**: 1층=시딩 대상(전역자·PX 꿀템 크리에이터, 전국 도달 → 시차 식별), 2층=측정 대상(부대 내 입소문 — 현역은 영리 금지라 시딩 불가), 3층=처치 가능 접점(PX 지점 샘플링·프로모션). `commercially_eligible=false`는 하드 제외.
- **KPI는 조회수가 아니라 검색 리프트와 재구매율**: 구매는 검색대(쿠팡·올리브영)에서, 매출은 재구매에서 일어난다. 조회수(avg_views)는 도달 지표로만 쓴다.
- **소모 주기**: 재구매(후행 신호)를 언제 기다릴지 정하는 제품 속성. 주간 루프는 선행 신호로 돌고, 분기 루프가 선행 신호의 예측력을 재구매로 보정한다.
- **데이터 획득 경로**: PX는 위탁판매라 품목별 전국 정산은 확보 확실, 지점별 셀스루는 부대별 발주량 프록시(낮은 재고율 가정) — 신호마다 `acquisition`(method·granularity·confidence)이 필수이며, 획득 경로 없는 신호는 스키마가 거부한다.
- **리프트는 반드시 처치 vs 대조**: 절대치 비교 금지. 리프트형 신호는 `control_definition`(대조의 정의)이 없으면 스키마 검증에서 거부된다.

## 판단 기준 (경계)

자동으로 하는 것: 처치/대조 배정, 시차 설계, 코드 발급, 브리프 생성, 신호 집계와 스코어 갱신, 예산 재배분 추천, 판단 불가 보고.

하지 않는 것:
- **안전성 플래그(`brand_safety_flags`) 크리에이터의 기용 결정** — 자동 배정에서 제외하고 '인간 판단 대기' 목록으로만 분리한다.
- **커뮤니티 슬롯 선택과 메가 인플루언서 베팅** — 시스템은 베팅의 근거 데이터를 만들 뿐, 베팅은 인간의 몫.
- **크리에이터 귀속이 불가능한 신호의 예측력 판정** — 커뮤니티 단위 신호(검색·셀스루)는 커뮤니티 단위 재구매 데이터가 생기기 전까지 분기 검정을 보류한다(`acquisition.granularity` 기준).

## 판단이 어려울 때 / 정보가 부족할 때

추측 금지. "판단 불가 + 필요한 데이터/조치"를 보고하고, 전제가 없으면 실행을 거부한다(exit 2).

- 배정 가능 쌍 < min_sample → 해당 신호 제외 + "취급 지점 쌍 추가 확보" 보고
- 시딩 가능 크리에이터 0명 / 예산 내 선정 가능 후보 0명 → 실행 거부 + 필요한 조치 보고
- 분기 보정 표본 부족(재구매 3건 미만)·신호 무변동 → 가중치 유지 + 판정 보류 보고
- 처치/대조 배정 전면 불가(적대 케이스) → 지점 신호 없이 강등 진행하되 제한 사항을 증거 패키지에 명시

검증: `scripts/verify_harness.py`(인과 검출·CPA 학습곡선·프록시 보정 실측), `scripts/test_decision_coverage.py`(결정 커버리지 + 브랜치 커버리지). 세부는 저장소 루트 `README.md`와 `data/verification/report.md`.
